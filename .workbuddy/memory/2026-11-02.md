# 2026-11-02

## 修复 Search Console「网页会自动重定向」导致全站不收录

### 根因（按影响面排序）

1. **主域名不一致（决定性）**：Vercel 把 apex `temstream.cloud` 308 跳转到
   `www.temstream.cloud`，但 `lib/site-config.ts` 的 `SITE_URL` 写的是 apex。
   结果 sitemap 里 20 条 `<loc>`、每页的 `rel=canonical`、`hreflang`、
   `og:url`、JSON-LD `@id`、`robots.txt` 的 `Host`/`Sitemap` **全部指向一个
   会 308 的 URL** → Google 把全站判为「自动重定向」并拒绝收录。
2. `/` 按 cookie + accept-language 选语言再 307 跳转 → 目标不确定（Googlebot
   不带 Accept-Language、Bingbot 带），属"请求头相关的软重定向"。
3. `/en/box`、`/en/box-faq` 用 `redirect('/zh')` 跳到首页（跨语言 + 跳首页，
   Google 明确不建议），并因此进入重定向报表。
4. `/zh/box` 的 `alternates` 仍然输出 `hreflang="en" → /en/box`（一个会跳转的
   URL），等于主动告诉 Google 去爬那条重定向链。
5. 早期为绕开 middleware rewrite 死循环打开了 `skipTrailingSlashRedirect`，
   导致 `/zh/wan/` 与 `/zh/wan` 都是 200，只靠 canonical 收敛。

### 改法

- `lib/site-config.ts`：`SITE_URL` 兜底改为 `https://www.temstream.cloud`（真正
  返回 200 的 host），并写清"改主域名必须同步改这里和 env"。
- `middleware.ts` 重写：全部 307 → **308**；`/` 固定跳 `/zh`（不再嗅探语言）；
  无前缀的**已知**路径才补前缀（白名单来自 `SITE_PAGES`+`ZH_ONLY_PAGES`）；
  未知路径直接放行交由路由 404，消除"重定向 + 404"双跳。
- `lib/seo.ts`：`makeAlternates(locale, path, availableLocales = routing.locales)`，
  zh-only 页传 `['zh']`，不再输出指向不存在页面的 hreflang。
- `app/[locale]/box|box-faq`：`redirect('/zh')` → `notFound()`（含
  `generateMetadata`）。
- `next.config.ts`：删掉 `skipTrailingSlashRedirect`，恢复尾斜杠 308 规范化。
- `app/layout.tsx`：删掉站点级 `robots: {index:true,follow:true}`（会在 404 页
  叠出与 Next 自动注入的 `noindex` 矛盾的 meta）；根 canonical 从 `/` 改 `/zh`。

### 验证（`next build` + `next start` 实测）

`/`→308 /zh、`/wan`→308 /zh/wan、`/download`→308 /zh/download、
`/zh/wan/`→308 /zh/wan、`/en/box`→404、`/foo`→404、sitemap 20 条全 www。

### 待用户操作

- 部署后确认 Vercel 里 `NEXT_PUBLIC_SITE_URL` **没有**被设成 apex（否则覆盖代码兜底）。
- Search Console 重新提交 sitemap，对核心页做"请求编入索引"，巡检报表观察 1–2 周。
